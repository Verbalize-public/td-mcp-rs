# Known-issues refactor — live validation

## Scope and outcome

The software fixes were implemented and exercised through **real MCP stdio**,
using the manual route explicitly authorized by the user. The harness MCP profile
was not modified. TD build **2025.32460 under Wine/Linux** was the available
complete installation; the original field report used **2025.33070**. Results
below must not be generalized to every TD build or native platform.

The central finding changed during live work: **GLSL POP does expose full compiler
logs through its bound Info DAT**, despite lacking `OP.compileResult`. The bridge
now uses that verified surface rather than declaring the consumer uncheckable.

Two additional MCP-boundary omissions were found live and fixed with regressions:

1. New wire codes were being collapsed to generic `tdmcp.mutate.step_failed` in
   top-level diagnostics. They now retain their actionable code and span.
2. Python emitted `shaderErrors`/`shaderNotes`, but Rust dropped those advertised
   summary fields. They now survive successful and partially failed mutations.
   Live bad/good POP writes returned `shaderErrors:1` / `shaderNotes:1`.

Compiler observation precedes operator error/warning reads when content is
requested, avoiding fresh compile results paired with stale earlier messages.
Without a usable POP Info DAT, status remains unsupported and bounded operator
errors are fallback evidence only. Passive observers and wrong bindings cannot
establish success.

| D1 path bases | On a POP parameter expression, `me.id` identified the POP; `parent()` and `op('..')` identified its parent. | D4 primitives | Viewed point dots, closed line-strip outline, open strip and filled surface outputs from the same scene. | Points were renderable; closed strips did not necessarily fill. Primitive choice and source selection must be isolated. |

| D10 merge names | Explicit separate inputs preserved CHOP channels a and b. | Lost wiring can masquerade as a naming problem; source/connector identities must be read back. |

Sparse visible geometry was sometimes classified as a black frame because its
mean RGB was low. Actual viewed pixels, not that heuristic alone, determined the
visual result. Screenshots do not establish FPS, GPU cost, or every animation frame.

## Reusable fixture and persistence

The delivered component contains only `scene`, `temporal`, `trigger_test`, and
`global_reset`. Its exposed controls are **Reset, Intensity, Scale**; no inert
Trail control was copied from the historical lightEngine. Global Reset calls
each stateful child reset. Camera, material, shader DAT, feedback and callback
references are owner-relative. The original audit network was retained separately.

Measured control effects before export:

- Intensity 1 → .25 changed maximum RGB 1 → .25, without changing alpha bounds.
- Scale 1 → .6 reduced rendered x bounds from 80..205 to 99..174.
- Global reset with three initialization frames gave Trail counts 256/320/576
  at offsets 0/1/5. The independently loaded `.tox` reproduced those counts.
- Fresh project PID 500781 had no original audit tree. Loaded references pointed
  only under `/project1/loaded_fixture`; GLSL POP compile state was compiled,
  recursive errors/warnings were empty, and the output was viewed.

Fixture construction caught and corrected two authoring mistakes rather than
mislabeling them TD defects: deleting an OP can delete docked DATs, so cleanup
checks validity; setting a string mode after assigning an expression reset the
parameter to CONSTANT on this build, so bindings use mode-before-expression and
verify actual evaluated paths. Partial fixtures were inspected and repaired,
not recreated or blindly replayed.
